# AGENTS.md — devtrim

Rust CLI (edition 2024, MSRV 1.88, pinned release toolchain 1.98.1). Sync code,
no async runtime, minimal dependencies. Ratatui 0.30 uses Crossterm 0.29 with
default features disabled; do not enable its optional layout cache without a new audit.

## Start and ownership

Read `MEMORY.md` and the current `memory/` journal, then `README.md`.
`src/app.rs` owns CLI dispatch; `src/ops/` owns category scan/apply;
`src/safety.rs` owns deletion validation; `src/journal.rs` owns audit records.
`src/tui.rs`, `src/analyze.rs`, and `src/status.rs` own the terminal surfaces.
Read `SECURITY.md` before changing an authority boundary and
`CODING_STANDARDS.md` before reviewing. The user's task is the specification
unless they name another source; pin the starting commit for change reviews.

Record existing edits before writing. Assign independent agents disjoint files;
the primary agent integrates and verifies. Stay in this checkout unless an
isolated worktree is authorized. Give an authorized worktree its own
`CARGO_TARGET_DIR`, test HOME, benchmark corpus, and evidence directory.
Never run cleanup against the developer's real HOME to test a change.

Launch delegated build tools with `CARGO_HOME`, `NPM_CONFIG_CACHE`,
`UV_CACHE_DIR` and `UV_TOOL_DIR` scoped inside this checkout and inherited by
child commands; do not rely on a worker remembering per-command cache flags.

## Agent execution

For Fable 5.1 and GPT-6 Astra, specify the outcome, preserved boundaries,
verification, and stopping condition. Batch independent reads, edit targeted
hunks, and keep useful local work moving during independent reviews. Run the
smallest meaningful check first; widen for changed safety boundaries and final
delivery. A failed gate needs a diagnosis, not repeated unchanged runs.
Preserve the baseline, ownership, decisions, evidence paths, and remaining work
across compaction. Model/effort selection belongs to the harness, not this repo;
verify availability before claiming a model ran.

These procedures follow the [Fable 5.1 guide](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1)
and [Astra guide](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra),
checked 2026-09-04. User instructions take precedence over skill procedures.

## Conventions
- `dashboard` is a private offline HTML snapshot, never deletion authority. It reuses existing category scans without widening their roots, copies fresh preview commands only, distinguishes logical inventory from filesystem available space, preserves the apply journal, and keeps hostile paths inert under hashed CSP. Retained detail is bounded; omitted measured bytes remain in totals, and unreadable inputs are disclosed with nonzero status. Existing report outputs are never overwritten.
- Every cleanup category = one file in `src/ops/`, implementing the `Op` trait.
- Findings use typed actions. Confirmation flags may bypass a gate but MUST NOT add or widen actions.
- Apply consumes only exact previewed findings; never rescan for deletion targets after confirmation.
- `trash-empty` omits direct Trash children named as an ASCII-case variant of `.git`, warns, and leaves them in place so one protected item cannot block other exact previewed children. An item whose size cannot be measured (an unreadable folder inside it) offers nothing and is named in one `project::unread_folders_finding`; the others are still listed and purged and the run exits nonzero. Apply continues past an item the sink refuses — a trashed project still holding its repository — recording each refusal so the run reports nonzero. Each direct Trash child is granted uv's marker (`safety::VerifiedTarget::grant_trashed_markers`) under the same shape and tag checks, so the uv cache `clean caches` moved there can be purged. The same grant (`MarkerGrant::owned_permissions`) lets the permanent sink add owner write and search permission, through each folder's open handle and just before emptying it, to a read-only folder the current user owns, so the Go module cache `clean caches` moved there can be purged too; a folder owned by another user still refuses, and a removal refused before anything was removed puts back every permission it added. Every other permanent removal refuses a tree with such a folder whole, before removing anything (`Writability::Require`). `trash-empty --only-devtrim` narrows the purge to what devtrim itself moved to the Trash: the sink journals each Trash move with the item's device, inode and birth time (`journal::TrashedIdentity`, captured before the move, which keeps them while the Trash renames the item), and only a direct Trash child matching a successful `trash` record is offered, filtered before anything is measured. The selection only narrows; the field is additive, accepted on `trash` records only, and absent from older records, which therefore never match; a history that cannot be read whole refuses the command and offers nothing, since the missed record could be the one that tells an item apart.
- **Deletion-list evidence.** Every added or widened deletion-list entry carries evidence for its exact scope: the owner, the observed contents, and why removal is appropriate. Cite specific vendor documentation or a versioned owner source. Where neither exists, say so explicitly, name what was observed, and state the limit — an empty directory or a cache-like name is not evidence. A parent entry needs evidence for the whole subtree it authorizes. `safety::DeletionEntry` and `HistoryRoot` make the field required, so omission will not compile and a blank one will not pass; whether the cited source actually supports deletion stays a hard review requirement no gate can settle.

- An owner-reported cache root (`brew --cache`, `npm config get cache`, `go env GOMODCACHE`) is resolved to its real path before it is judged, as `$HOME` is, so a home reached through a link does not make the cache look foreign; a root that does not exist yet is kept as reported.
- Homebrew's cache (`brew --cache`) is offered whole unless it is the standard `~/Library/Caches/Homebrew` and a direct child is a Git repository — the clone Homebrew's Git download strategy keeps per Git-sourced formula (`<name>--git`), judged by its marker, not its name — in which case its other non-empty, non-link direct children are offered under `TargetAuthority::BrewCacheEntry` and the clones stay; apply reasserts that shape (parent exactly the standard cache, neither a link nor a repository), so an entry nested inside a clone is refused before the sink.
- `caches` scan contains an unmeasurable cache to itself: a cache whose `dir_size` fails (an unreadable folder inside it, a size overflow) offers nothing and is named in one `project::unread_folders_finding` error finding, so the run exits nonzero while the other caches are listed. A failing owner command (`npm`, `brew`, `go`) is one error finding for its own cache alone, as an unmeasurable cache is; `npm` is asked with `npm_config_logs_max=0` and `npm_config_update_notifier=false`, so a preview writes no debug log or update-check file into its cache. Gradle's default `~/.gradle` is resolved to its real path, as `GRADLE_USER_HOME` is, and judged inside the home folder; `installers` names a linked `Downloads` or `Desktop` in a warning and offers nothing from it, since the sink refuses a target below a link.
- `caches` offers Gradle's `caches` and `wrapper/dists` (`GRADLE`, relative to `GRADLE_USER_HOME`, default `~/.gradle`; never that folder, which holds `gradle.properties` and `init.d`; a relative `GRADLE_USER_HOME` or one outside the home folder is skipped with a warning, and so is a Gradle home that is or lies inside a Git repository, judged as `project::owning_repo` judges one). Each folder must also hold what Gradle writes there, at scan and at apply (`holds_gradle_layout`, Gradle 9.8.1 user-home layout): `caches/modules-2`, or a `wrapper/dists` child named `gradle-<version>-bin` or `-all`; `GRADLE_USER_HOME` alone never makes a folder a cache. Gradle locks them only among its own processes and cleans them when its daemon stops (Gradle 9.8.1 docs), so while `pgrep -a -f` finds Gradle's daemon (`org.gradle.launcher.daemon.bootstrap.GradleDaemon`), a daemon-less build (`launcher.GradleMain`) or the Wrapper (`wrapper.GradleWrapperMain`) they are left out with a diagnostic, and apply probes again at each Gradle finding and refuses it; a failed probe is one error finding for Gradle alone.
- The Go module cache is the folder `go env GOMODCACHE` reports, asked from `$HOME` with `GOTOOLCHAIN=local` (go.dev/doc/toolchain: otherwise a `go.mod` there could make `go` download a toolchain), resolved like the other owner roots, and offered only when it lies inside the home folder and holds Go's `cache/download` (go.dev/ref/mod, "Module cache"); apply asks `go` again and requires the same folder, only for a target holding that `cache/download`. `go` absent offers nothing; `go` failing is one error finding for the Go cache alone. Go makes the cache read-only, so apply refuses a permanent removal when any folder in it is read-only, and a move to the Trash when the cache folder itself is — refusing before the sink, never a half-removed cache.
- `caches` apply continues past a refused finding, recording every failure so the run still reports nonzero. The list spans unrelated tools and one entry can be refused for a reason of its own — uv busy with its cache, a nested repository — so stopping at the first failure would block every cache listed after it.
- `artifacts` and `node_modules` apply preflight every finding before changing anything — a failed probe or recheck there stops the whole plan untouched — then judge each finding again, with fresh Git and tracked-file observations and the initial build-process snapshot, just before its own removal, and continue past a finding that recheck or the sink refuses, recording each failure. Removing the earlier findings takes time, so a repository that becomes active meanwhile keeps its output.
- A repository at or above the home folder (dotfiles kept as a repository at `~`) owns nothing: `project::owning_repo` returns no owner for it (`safety::holds_home`, failing closed), so a project under it with no repository of its own is not judged at scan or at apply. Its last commit says nothing about that project.
- Feature evals (`tests/evals.rs`, `tests/eval_system.rs`, `tests/eval_reports.rs`, `tests/eval_safety.rs`) run every command through the real binary against a planted fixture: positives the feature claims, and one near miss per documented exclusion. A preview must leave the fixture byte for byte unchanged and an apply must change exactly the previewed targets (`support::Tree`, whose own controls prove it reports each kind of unauthorized change); the journal must show each removal write-ahead. Drift between consent and apply is driven inside one invocation through `/usr/bin/script`. Only assertions named by `planted-violations.py` are mutation-proven; the other eval assertions remain review obligations. Stubs prove devtrim's side of external tools; `scripts/tests/native-docker.sh` proves Docker against a real disposable engine, while the real Trash move, real `simctl` and the maintenance tasks stay unproven end to end.
- `xcode` scan contains a DeviceSupport or DerivedData folder it cannot read or measure (`dir_size`, the package-folder checks, a directory entry or its type) to that folder: it offers nothing and is named in one `project::unread_folders_finding` error finding, so the run exits nonzero while every other folder is judged; a support directory itself that cannot be read still fails the category.
- `xcode` apply continues past a refused finding in the same way. A DerivedData folder that holds a Git repository is refused by the sink, so stopping at the first failure would strand every build tree after it; each refusal is recorded and the run still reports nonzero.
- The uv cache is removed only under uv's own lock: a running uv holds a shared `flock` on `<cache>/.lock` where the filesystem supports shared locks, as APFS does, and `uv cache clean` takes it exclusively (uv 0.9.24 `crates/uv-cache/src/lib.rs`, `crates/uv-fs/src/locked_file.rs`; std `File::lock` is `flock(2)` on macOS). Apply refuses a cache reached through a symlink or symlinked ancestor before creating anything, then opens the lock no-follow and non-blocking, creating it as uv does, takes it exclusively without waiting, and holds it until the cache has moved; a held lock refuses only that finding. The lock is also the grant: `safety::UvCacheLock` has no constructor but taking that lock, and outside the Trash only a target granted by a lock on its own exact root lets the sink tolerate uv's marker, so a `CACHEDIR.TAG` root reached through `artifacts` — a repository-local `UV_CACHE_DIR` — keeps the refusal and can never be removed under a running uv. `trash-empty` grants the marker to direct Trash children, where no uv uses the tree, under the same shape and tag checks.
- `agents` apply continues past a refused finding, like `caches`, and reports an age-gate refusal as history that became active rather than as a target outside its namespace. The gate is re-read at apply, so a session resumed between preview and apply is an expected refusal that must drop only its own finding.
- Codex standalone releases are a third closed `agents` authority, `CODEX_RELEASES`, a `DeletionEntry` whose evidence is required. A release is offered only when the installer lock and `current` symlink prove an older direct-child layout-v1 package with canonical version numbers, and a system-wide `lsof -d txt` snapshot reports no process executing a file inside it. The `lsof` probe explicitly requests descriptor and name fields; failure or a mapping without an absolute name refuses release cleanup. Apply rechecks eligibility and probes liveness again at each release rather than once per plan. The snapshot cannot see every other user's process or one started after the probe. Current, newer, same-core, staging, and unknown layouts remain outside this authority. Vendor files are opened no-follow, non-blocking and close-on-exec. A busy or unverifiable installer refuses only its release findings during apply.
- `~/.claude/jobs` is never a history root: it is the background-session supervisor's state (`state.json`, `timeline.jsonl`, `tmp`), a pinned session stays alive while idle and a shed one is woken from it, and the `pins.json` beside it is a liveness file a closed category must not need to consult.
- A `HistoryRoot` in `agents` earns its place only when the space it offers is worth the preview lines it costs. Measured against the development machine, Codex lanes gave 558 findings for 0.25 GB, its `.tmp` tree 324 for 0.07 GB, and the Claude Code file-edit history 123 for 0.10 GB; all three are excluded, and what remains offers 4.02 GB in 57 findings.
- Every human apply prints the data-loss notice; every interactive mutation confirms regardless of danger, `trash-empty` included. `-y` skips y/N only; `--yolo` skips all interactive prompts. Operation-specific acknowledgments such as `trash-empty --confirm=<gb>` still apply, and that acknowledgment is measured over the exact previewed findings, never the whole Trash. `--json` keeps stdout one document and prints no notice; on a terminal an apply without `-y` or `--yolo` still asks on stderr (the drift evals answer that prompt through `/usr/bin/script`). A non-interactive refusal names what the plan needs: `-y` for y/N plans, `--yolo` for typed-size plans.
- Global flags are capability-scoped: commands reject mutation flags they cannot honor. `scan --shred` may change previewed actions; Docker and simulator cleanup reject `--shred` because they execute typed commands rather than filesystem deletion actions; `trash-empty` accepts apply/confirmation flags but rejects `--shred`; report-only commands accept no mutation flags.
- Unknown activity, ownership, symlink resolution, owner-command status, configuration fields, or size measurement fails closed. Failing closed is scoped to what failed, never wider: a repository whose Git query, tracked-file check, tree search or size measurement fails offers nothing — not even a finding judged before the failure — and is reported as one `Action::Info` finding with no target carrying `scan_error` (`project::unjudged_finding`), so the run exits nonzero while every other repository is judged; folders the project walk cannot read (`project::UnreadFolder`) are reported the same way, one finding per category (`project::unread_folders_finding`), and their subtrees are not entered, while a scan root itself that cannot be read still fails; a failed liveness probe still fails its whole category.
- `scan_all` owns shared liveness/Git observations for one preview, including failures. Standalone scans start fresh; apply must never reuse preview observations.
- `scan_all` runs the ten categories concurrently on scoped threads and joins them in registry order, so findings and errors stay byte-identical to a serial scan; a panicked scan thread becomes that category's error. Apply is never parallel, because the journal serializes each attempt/result pair. Cross-category diagnostics arrive in completion order, not registry order.
- `Op` has exactly one scan entry point, taking `&ScanObservations`. Observations live for exactly one scan: each repository's Git date and the build-process probe are computed once, the mutex is released before the subprocess runs, and a failed probe is memoized and re-yielded to every category so it blocks rather than silently passing.
- Hugging Face cleanup targets only `~/.cache/huggingface/hub`; its parent, tokens, and settings are never built-in cache authority.
- Filesystem findings retain an exact internal `PathBuf`; serialized display text is never parsed back into deletion authority.
- Only `safety::validate_path_for_deletion` creates `VerifiedTarget`; only the private sink in `src/ops/mod.rs` consumes it. Raw filesystem deletion anywhere else is a blocking ast-grep violation.
- Apply derives Trash versus permanent mode from the previewed typed `Action`, never from a runtime flag. The Trash move goes through `trash_context()` in `src/ops/mod.rs`, which selects `NSFileManager` (`trash::macos::DeleteMethod::NsFileManager`), never Finder's AppleScript, which needs Automation permission; a real move writes to the developer's own Trash, so no test performs one.
- Permanent deletion must be explicit in preview and danger scoring.
- Never add shell-string execution. Process execution uses a fixed program; a dynamic argument is allowed only when a closed typed authority validates and carries it.
- Every scan and apply subprocess runs through `process::BoundedCommand::output_within` with one of three limits in `src/process.rs`: `QUERY_TIMEOUT` (120 s: Git, `simctl`, `docker`, `npm`, `brew`, `go`), `PROBE_TIMEOUT` (180 s: `pgrep`, `lsof`; a system-wide `lsof` took 16 s at load average 300 and load reached about 950) and `MUTATION_TIMEOUT` (900 s: the typed Docker, simulator and maintenance commands an apply runs). Past the limit the child is killed and reaped and the call fails with `TimedOut` naming the program and the limit; it is never `NotFound` and never an empty probe, so a timed-out liveness probe refuses and the affected repository or category fails while the others complete. `no-unbounded-subprocess` rejects `.output()`, `.status()` and `.spawn()` in `src/` outside tests, `src/process.rs`, `src/status.rs` and `src/uninstall.rs`. Each command leads a process group of its own and a timeout kills the whole group (`rustix::process::kill_process_group`, before the leader is reaped, so its id cannot be reused); a group of its own never receives the terminal's Ctrl-C, so every run but a full-screen view installs `process::exit_on_interrupt` (`signal-hook`, SIGINT, SIGTERM and SIGHUP, since closing the terminal signals devtrim and never the groups): live groups sit in one registry in `src/process.rs`, registered when the spawn finishes (a counter of spawns in flight covers the gap, and an interrupt waits for it for at most two seconds) and unregistered under the same lock that reaps the leader (a reaped leader's group is never signalled); a signal kills them all and exits 130, 143 or 129 without writing any message, which could block on a full stderr, and a second signal exits at once. A SIGINT ignored at startup (a background job of a non-interactive shell) is replaced, since there is no safe way to read the earlier disposition, and so is a SIGHUP ignored by `nohup`: such a run stops when its terminal closes. The full-screen views — the TUI, `analyze` and `status --watch` — install `process::forward_interrupts` instead, before the terminal changes (raw mode, where Ctrl-C is a key, and a terminal only its own thread may restore): each loop restores the terminal through `tui::restore_and_exit`, then calls `kill_and_exit` with the signal, during an apply too, which `scripts/tests/read-only-views.py` proves for `analyze` on SIGTERM and `status --watch` on SIGINT; a second signal kills and exits at once without restoring it. A descendant holding the output after a clean exit is abandoned, not killed. The 900 s limit covers the typed Docker, simulator and maintenance commands.
- `simulators` deletes only unavailable devices. Working simulators are one report-only `Action::None` finding sized from simctl's `dataPathSize`, never a tree walk, parsed apart from the device authority and omitted with a diagnostic when a size is missing or malformed; apply skips it on actionability and returns before measuring when nothing in the plan is actionable, because the CLI applies such plans. Exactly two `xcrun` answers mean there is nothing to manage, a diagnostic rather than an error: `xcrun --version` exiting 1 with `invalid active developer path` or `missing DEVELOPER_DIR path` (no developer directory), and `xcrun simctl` exiting 72 with `unable to find utility "simctl", not a developer tool or in PATH` (the Command Line Tools without Xcode); any other failure still fails the category.
- Only `Finding::command` creates command authority from the closed `CommandAuthority` enum; apply verifies that capability, its validated arguments, and its serialized `Action` before execution. Docker authority binds an absolute local Unix-socket endpoint; simulator authority binds one exact UDID.
- Docker volumes are never pruned. Xcode Archives are never pruned.
- Xcode and Swift toolchain apply must reassert the scanner's exact direct-child target shape before calling the shared deletion sink. Xcode offers and applies only real directory children of `iOS DeviceSupport`, `watchOS DeviceSupport`, `tvOS DeviceSupport`, `visionOS DeviceSupport` (the names LLVM's lldb looks for, llvm-project 82911de `GetDeviceSupportDirectoryNames`; the pre-Xcode-27 `XROS`/`xrOS` folder is left out, since its case is unsettled and a case-only difference from the folder on disk is refused at the sink) and `DerivedData`; a file (Finder's `.DS_Store`) or a symlink beside them is never a symbol or build tree. The one deeper shape is a DerivedData folder holding SwiftPM package checkouts (a non-empty `SourcePackages/checkouts`): each checkout is a Git clone the sink never removes, so the folder is offered as its real directory children except `SourcePackages` (any ASCII case), which stays. A folder that is itself a Git repository or worktree (a top-level Git marker) is never split: its directories are that repository's worktree, which the sink, checking each directory alone, could not see.
