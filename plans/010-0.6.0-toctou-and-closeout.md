# Plan 010 — 0.6.0: TOCTOU-hardened sink, visibility, rotation, signing

Close every follow-up 0.5.0 left open, grounded in primary-source research
(Rust CVE-2022-21658 remediation, cap-std, Apple signing docs, lumberjack
rotation). Success: the deletion sink verifies target identity from an
anchored parent handle, `devtrim largest` answers "where did my disk go"
read-only, the journal rotates without ever losing an in-flight record, every
shipped binary carries a coherent signature, the demo video shows the current
interface, and 0.6.0 ships through the attested chain.

## Tickets

### T1 — Identity-verified, parent-anchored deletion sink (P1)
`Finding::new` captures the target's `(st_dev, st_ino)` at preview time
(internal, never serialized). The sink refuses actionable filesystem findings
whose identity is missing or no longer matches: `remove_path` opens the parent
directory as a `cap_std::fs::Dir`, re-reads `symlink_metadata(leaf)` through
that handle, compares identity, then deletes through the same handle
(`remove_file` / `remove_dir_all` — cap-std's dirfd-anchored implementation,
the same shape std adopted after CVE-2022-21658). Trash stays path-based
(macOS has no fd-anchored Trash API): identity is re-verified through the
parent handle immediately before `trash::delete`, and the residual rename race
is documented with cap-std-style honesty, not claimed away. ast-grep rules
gain method-call patterns (`$RECV.remove_file($T)` etc.) with positive
controls so the new primitives cannot be used outside the sink.
New dependency: `cap-std` (Bytecode Alliance, MSRV 1.70, actively maintained).

### T2 — `devtrim largest` (P2, closes the last audit gap)
Read-only disk visibility: one traversal per root attributing file sizes to
depth-≤2 directories, top N (default 20) as `Action::Info` findings, standard
one-document JSON envelope. Report-only leniency: unreadable entries are
skipped and disclosed as a count, never silently. No TUI entry in 0.6.0.

### T3 — Journal rotation (P2)
Writer-owned, open-time-only, shift-and-rename (lumberjack pattern): at
`Ctx` construction, if the journal exceeds 10 MiB, rotate `.2→.3`, `.1→.2`,
`current→.1` under an flock; never mid-apply, never copy-truncate. History
reads `.3 → current` concatenated so attempt/result pairs can never split
across a rotation. Rotation failure warns and keeps appending — the cap fails
closed for size, open for the audit record. Appends `sync_data` so the record
lands before success is claimed.

### T4 — Signing (tier 1 now; notarization runbook)
The release workflow ad-hoc signs the built binary explicitly
(`codesign --force --sign -`) and verifies it (`codesign -v`) before
packaging — field reports show linker-only signatures being rejected by newer
macOS policy. Developer ID signing + `notarytool` notarization is documented
as a precise runbook (SECURITY.md): it requires exporting the local
"Developer ID Application" certificate and creating notary credentials —
credential decisions that stay with the maintainer; the workflow path is not
implemented until it can actually run (an untestable conditional signing path
in the release chain is risk, not safety). Distribution reality documented:
brew and curl installs never quarantine; browser downloads do.

### T5 — Demo video refresh
The Remotion menu matches the current TUI (Build artifacts entry, `i` for
iCloud status), re-rendered to `media/demo.mp4` with captions and the landing
transcript kept accurate.

### T6 — Docs + release
SECURITY.md rewrites the TOCTOU limitation honestly (what is now anchored and
identity-verified; what remains path-based and why), README/MANUAL/AGENTS
cover `largest`, rotation, identity verification, and signing. Version 0.6.0
(new features → minor), staging beta then exact-byte production promotion,
tap formula bump.

## Decisions and rejected alternatives

- **cap-std over hand-rolled openat/unlinkat**: reimplementing race-free
  recursive deletion is the highest-risk code in this class; std/cap-std are
  the audited implementations. Rejected: raw rustix recursion.
- **Identity captured at preview, verified at delete** — devtrim's real
  TOCTOU surface is the minutes between preview and apply, not microseconds
  inside removal; this closes the root-swap gap the CVE class describes.
- **Rejected: implementing untestable Developer ID workflow steps.** The
  supply-chain boundary (signing secret never reaches a job that executes
  repository code) is designed in the runbook; machinery lands when
  credentials exist to prove it.
- **Rotation at open only** — logrotate copytruncate measurably loses lines;
  bash-history truncate-in-place is the canonical anti-pattern. The journal
  is deletion evidence; the cap yields, never the record.

## Pre-mortem

1. cap-std semantics differ from std on some edge (symlink leaf, non-UTF-8
   names) → the corpus of existing sink tests (non-UTF-8 identity, symlink
   ancestor, forged targets) must pass unchanged; add symlink-leaf and
   dir-swap tests with sentinels.
2. Identity capture breaks findings for vanished paths → identity is
   `Option`; only actionable filesystem findings require it at the sink.
3. Rotation races a concurrent devtrim → flock; on contention, skip rotation.
4. MSRV: cap-std 1.70 < 1.88 ✓, verified by the mandatory MSRV gate.
5. Video re-render drifts from real TUI → transcript and captions updated
   from the rendered frames, not memory.
