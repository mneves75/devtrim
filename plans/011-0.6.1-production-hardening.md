# Plan 011 — 0.6.1: fail-closed production hardening

Status: DONE — immutable beta3 and exact-byte production promotion verified.

Objective: ship a patch release that makes devtrim's existing safety promises
true under malformed input, concurrent local processes, filesystem races, and
release-credential compromise. The audience is macOS developers using the CLI
and the maintainer operating the release chain. Success means every confirmed
P1–P3 finding has a regression, all documented release gates execute, staging
publishes an immutable `-betaN`, and production promotes those exact bytes only
after explicit approval.

Constraints: synchronous Rust, MSRV 1.88, no new deletion authority, no whole
worktree deletion, one JSON document per `--json` invocation, minimal
dependencies, and no project/dependency code executing with release-write or
OIDC credentials. The landing page stays on the current stable version during
beta staging.

## Alternatives considered

Evaluation weights: safety/correctness 40%, verifiability 20%, release-chain
integrity 15%, simplicity 15%, maintainability 10%.

| Approach | Character | Result |
|---|---|---|
| Document limitations only | Conservative | Rejected: preserves known contract violations. |
| Fix only reproduced crashes/output defects | Minimal | Rejected: leaves deletion, journal, and release boundaries exposed. |
| Patch findings without changing release automation | Narrow | Rejected: local review could still run project code beside publication credentials. |
| Freeze features and harden shared boundaries | Long-term quality | Selected: fixes the few choke points every operation inherits. |
| Replace deletion with a privileged helper/daemon | Ambitious | Rejected: materially larger attack surface and operating burden. |
| Remove permanent deletion and publication automation entirely | Assumption-challenging | Rejected: safer in isolation, but abandons explicit product requirements instead of making them verifiable. |

The selected approach combines a feature freeze with boundary-first fixes. It
adds complexity only where the risk is shared: deletion, journal integrity,
machine-readable output, scanners, and artifact publication.

## Tickets

### T1 — Truthful CLI and scanners (P1)

Wrap Clap failures in the one-document JSON contract, return nonzero for every
partial/failed operation, make empty apply summaries zero, and make Git,
filesystem, liveness, Docker, simulator, and iCloud evidence fail closed.
Preflight every candidate before the first mutation.

### T2 — Permanent-deletion boundary (P0)

Recheck preview identity including macOS generation, quarantine before
permanent deletion, recurse through directory handles, refuse device crossings,
revalidate configured protect aliases, and reject Git markers at every depth.
Keep the unavoidable Trash and parent-resolution windows explicit.

### T3 — Journal integrity (P1)

Hold rotation coordination from attempt through result, serialize complete
record appends, make read-only history wait for active guarded applies,
reverse-scan a bounded newest history tail with line and byte caps, pair legacy
records across generations in linear time, refuse symlinked journal path
components, tolerate Darwin's transient same-leaf first-creation `ENOENT` with
one descriptor-anchored CREATE-only retry, and keep `history` genuinely
read-only. The journal remains local audit evidence, not a tamper-evident log.

### T4 — Credential-separated release chain (P0)

Make the local script provenance-only; run deterministic gates and all five
bounded fuzz targets in read-only hosted jobs; give only the no-checkout
publisher write/OIDC permissions; pin action/tool identities; monitor and audit
the separate fuzz lockfile; require current default-branch head, immutable
releases, exact-commit CI, checksums, and signer-workflow-bound attestations.

### T5 — Documentation and release (P1)

Bump 0.6.1, update the changelog, manual, security model, maintainer guidance,
project memory, and explainer. Run the complete local proof, independent review,
and P3 autoreview; commit and push; stage `v0.6.1-beta<N>`; promote the same
archive to `v0.6.1` only after explicit confirmation.

## Pre-mortem and five-year test

- A nested worktree is erased inside an otherwise valid cache: reject `.git`
  at every directory during preflight and again during removal; prove the whole
  tree remains intact.
- A symlink redirects audit records or permissions: create/open every journal
  component descriptor-relatively without following symlinks; test both apply
  and history paths.
- Concurrent writers corrupt JSONL: lock each full append through `sync_data`
  and stress multiple writers.
- A stale commit or compromised build publishes: revalidate default-branch head
  before tagging/preparing/publishing and never expose publication credentials
  to checked-out code.
- Future maintainers trust prose instead of evidence: keep gates executable,
  positive-controlled, pinned, and colocated with the release workflow. Avoid a
  daemon, compatibility layer, or generalized cleanup DSL unless a measured
  requirement justifies their long-lived surface.

## Gates

Format, positive-control ast-grep, strict Clippy, full tests, MSRV 1.88, root
and fuzz lock audits, five 60-second fuzz targets, PTY TUI cancel, release-policy
tests, Bash/ShellCheck/actionlint, Gitleaks, TruffleHog, strict npm install/audit/
lint/format/build, arm64 release build, desktop/mobile real-UI inspection,
independent security review, and one closeout autoreview at P3.
