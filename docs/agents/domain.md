# Domain docs

devtrim has one domain context. Read the root `GLOSSARY.md` before exploring
or naming domain concepts. Read any relevant `docs/adr/` decision if that
directory exists; absent decisions do not block work.

Use the glossary's vocabulary in interfaces, tests and documentation. Resolve
a conflicting meaning before changing it. The glossary defines concepts, not
implementation plans. Record only consequential, hard-to-reverse trade-offs
as ADRs; ordinary reversible choices belong in the feature's task record.
