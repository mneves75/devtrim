# 2026-11-02 — 0.12.5: sizes on disk, history notice, per-item apply results

The owner reported three problems, none of which lost data ("fix: Três problemas
do devtrim que encontrei"), then asked to "verify and deploy prod", and approved
the production candidate `0c761f8` ("Promote 0c761f8").

- #77 fixes them: every size is allocated blocks (`safety::DiskUsage`, hard
  links once), as `du` counts; `devtrim history` says when it cut the list
  (`truncated`); the apply JSON carries `results`, one per actionable finding.
  A zero-block cache, agent cache or installer is no longer offered.
- The independent verifier (mneves-verify, Sol) passed all three on the real
  binary. `verify.sh offline` first stopped at a planted mutant that no longer
  compiled (the new `History` field); fixed in the mutant.
- The security gate took four rounds. One Sol could not read the ~30k changed
  source and test lines in full (A1 failed twice, no finding); the owner waived
  `gate:independent-acceptance` for 0.12.5 (to 11-08), which `release.sh`
  accepts for staging only. Four Sol verifiers then read disjoint quarters in
  full: no new finding, but two rated SEC-18 No for N-2 (results joined on lossy
  text, so a never-attempted item could read `ok`). #78 joins on the exact
  in-memory path; its test failed on the parent. The delta's Sol acceptance
  passed, so production did not rely on the acceptance waiver.
- Released `v0.12.5-beta1` and `v0.12.5` from `0c761f8`, Homebrew 0.12.5.
- Lessons: a full-read gate criterion over tens of thousands of lines needs a
  split reading from the start; `cargo metadata --offline` is no lockfile check

  empty HOME with npm 12 ("The cache option is protected"), which devtrim
  reports as the npm cache's own error.
