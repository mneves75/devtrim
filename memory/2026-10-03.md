The owner asked for more free space, a source review, a live run, and a release. Free space was

   `Payload/*.app/assets` bundles, and corepack's `pnpm/<v>/dist/node_modules`.

Fixes (tests first; each E2E test went red on the 0.10.4 source and green after):
- Unreadable folder: `project::UnreadFolder`, one error finding per category, subtree not
  entered; a root itself still fails. First built as a warning with exit 0, as for an
  unreadable default root; the Standards review cited `CODING_STANDARDS.md` S8 (a shorter plan
  with exit 0 is a defect; precedence above CLAUDE.md), so it became an error. On this Mac
  `purge` now exits 1 naming the Berlin `.fseventsd` until that folder is readable or gone.
- Unborn branch: `project::unborn_branch`, asked only after the activity query failed, fixed
  argv. Unborn = `symbolic-ref -q HEAD` ok and `rev-parse -q --verify HEAD` exit 1 with empty
  output. Probed on git 2.56.0: unborn and `--orphan` give rev-parse 1; a dangling HEAD gives
  rev-parse 0 (and `show-ref --verify` 128); a detached HEAD fails symbolic-ref. autoreview
  (Codex, P2) found that a `.git/refs/heads` turned into a file also reads as unborn — Git's own
  `log`/`status` call it "no commits yet" — so `refs verify` must succeed too (255 there, 0 for a
  real unborn repo). A second autoreview (full range) found a file holding a valid object ID at
  `.git/refs/heads` passes `refs verify`, so the rule is now "new repository": also no reference
  at all (`for-each-ref --count=1` empty); an `--orphan` checkout beside other branches now stays
  an error.
  With no reference at all HEAD cannot resolve, so the `rev-parse` check became redundant (a
  dangling HEAD makes `for-each-ref` exit 128) and was dropped: the rule is `symbolic-ref` ok,
  `refs verify` ok, `for-each-ref --count=1` ok and empty.
  A third autoreview found a branch turned into a dangling symbolic ref passes all three
  (`for-each-ref` omits dangling symrefs). Three rounds on one predicate: stopped patching ref
  corners and added Git's data-model invariant instead: `count-objects -v` must report an empty
  object store (no loose, no pack, no alternate). Every commit is an object, so whatever is
  still skipped truly has no commit; the ref checks keep frozen criterion 4 (objects deleted ->
  error) true.
  With that invariant the "listing prints nothing" check was redundant (a listed ref in an
  empty store names a missing object, so the listing fails) and was dropped. Final rule: empty
  object store + symbolic HEAD + `refs verify` ok + `for-each-ref --count=1` ok; each proven by
  a planted case on a fixture where it is the only catch.
  Then the advisor caught that "empty store" regressed the live repro: celld-motion had 27
  staged blobs (`git add` writes objects). Invariant corrected to "no commit object":
  `cat-file --batch-all-objects --unordered --batch-check=%(objecttype)` with no `commit` line.
  A staged-files fixture now covers it; live `purge` skips and names celld-motion again.
  Lesson: a stub that answers the probe hides what the probe sees; test the live case too.
  Fourth autoreview round: an unlistable object fanout folder makes `cat-file
  --batch-all-objects` skip it, print "unable to open ... Permission denied" on stderr and still
  exit 0 (reproduced on git 2.56.0). The listing must now also have empty stderr. My first
  fixture for it was vacuous (HEAD@{1} named nothing after `checkout --orphan`); it now takes
  the oid from refs/heads and asserts the fanout folder exists. If this predicate fails again,
  the owner's choice is to drop the new-repository skip: containment alone already keeps a new
  repository from emptying purge; it would then be an error that blocks only itself. It also found a `node_modules` candidate failing after its owner was known blocked only
  itself; a second scan root inside that repository could still offer. Now it vetoes the repository.
- Manifest: a `node_modules` needs a regular-file `package.json` beside it, at scan and apply.
  On this Mac 147 manifest-less ones were excluded: 116 in `.scratch`, 13 `dist`, 12 `.app`,
