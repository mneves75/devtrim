## 0.10.5: contain each failure to where it happened

The owner asked for more free space, a source review, a live run, and a release. Free space was
27 GiB; a read-only `devtrim scan` (installed 0.10.4) offered nothing from `purge`. Three live
defects, found one after another by routing around the previous one with explicit `--root`s:

1. A root-owned `.fseventsd` (mode 700, left by a mounted disk image) in
   `berlin-os-platform/.scratch/...` refused the `CACHEDIR.TAG` probe. That one folder failed
   `node-modules` and `artifacts` whole.
2. `~/dev/celld-motion`, a fresh `git init` with no commits, failed the activity query and
   emptied `purge` again.
3. The preview that finally appeared offered `node_modules` inside `.xcarchive` and unpacked
   `Payload/*.app/assets` bundles, and corepack's `pnpm/<v>/dist/node_modules`.

Fixes (tests first; each E2E test went red on the 0.10.4 source and green after):
- Unreadable folder: `project::UnreadFolder`, one error finding per category, subtree not
  entered; a root itself still fails. First built as a warning with exit 0, as for an
  unreadable default root; the Standards review cited `CODING_STANDARDS.md` S8 (a shorter plan
  with exit 0 is a defect; precedence above CLAUDE.md), so it became an error. On this Mac
  `purge` now exits 1 naming the Berlin `.fseventsd` until that folder is readable or gone.
- Unborn branch: `project::unborn_branch`, asked only after the activity query failed, fixed
  argv. Unborn = `symbolic-ref -q HEAD` ok and `rev-parse -q --verify HEAD` exit 1 with empty
  output. Probed on git 2.56.0: unborn and `--orphan` give rev-parse 1; a dangling HEAD gives
  rev-parse 0 (and `show-ref --verify` 128); a detached HEAD fails symbolic-ref. autoreview
  (Codex, P2) found that a `.git/refs/heads` turned into a file also reads as unborn — Git's own
  `log`/`status` call it "no commits yet" — so `refs verify` must succeed too (255 there, 0 for a
  real unborn repo).
- Manifest: a `node_modules` needs a regular-file `package.json` beside it, at scan and apply.
  On this Mac 147 manifest-less ones were excluded: 116 in `.scratch`, 13 `dist`, 12 `.app`,
  CMake object mirrors, pnpm-store links, and one 4 KB `sinal/web/node_modules`. No real install.
- Repository containment (owner chose "Contain to that repo", resolving open item 2): a failing
  repository is one `Action::Info` finding with no target carrying `scan_error`
  (`project::unjudged`); its already-judged findings are withheld; the run exits nonzero.

Open after 0.10.5 (owner decisions or later patches):
- Homebrew cache holding a `*--git` clone is offered but always refused by the sink. Options:
  offer it as children minus `*--git`, or a typed `brew cleanup` command (which also removes old
  kegs, so not a pure cache action).
- `trash-empty` cannot be narrowed from the CLI; a shared Trash makes that matter.

Lesson: a fail-closed rule implemented as "fail the category" turns every odd folder on a real
disk into an empty preview. Scope the refusal to what failed, and keep the error visible.
