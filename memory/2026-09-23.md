## 0.9.7: review of 0.9.5 and 0.9.6

Pinned `v0.9.4..HEAD` (d019459, 2d00795). Four independent read-only passes:
Standards, Spec, Security, and web research (Rust/crates/Actions currency,
lsof/pgrep man pages, cleanup-tool incidents).

Accepted and fixed, each test shown failing on a mutant first:

- S8: the working-simulator disclosure saturated its byte total; now checked,
  and overflow drops only the disclosure with a diagnostic.
- Spec: no test covered a mixed simulator plan. Apply stops at the first error,
  so a count-based assertion could not tell the disclosure from the forgery;
  the forgery now carries its own refusal ("altered simulator action").
- S12: the pgrep ancestor test ran a `format!` script through zsh. It now uses
  a uniquely named `/usr/bin/time` symlink (verified: takes the link's name,
  propagates the child's status). S12 lists it as a test-only variable program.
- The real lsof race test calls the production `lsof_cwds_of`.
- New planted case `xcode/non-directory-target`; gate reports 15 caught.

Narrowed rather than fixed: Security's low finding that a reported PID reused
by a new build within the recheck keeps its first directory. Re-running lsof
over the whole set would reintroduce the 0.9.6 race; the window is no wider
than a build starting after a clean probe. SECURITY.md now says so.

Falsified: a zombie build process does not block liveness — macOS shows it as
`<defunct>`, so `pgrep -x` never lists it (checked twice independently).

Rejected: dependency bumps (clap 4.6.7, clap_complete 4.6.11, trash 5.2.9,
toml 1.1.6, rustix 1.1.5) fix nothing relevant; `cargo audit` clean; Rust
1.98.1 still latest stable; every pinned Action is on its latest release.

re-resolved 156 lockfile lines (added wit-bindgen). Edit only the version line
and confirm with `cargo metadata --locked`.

## 0.9.7-beta2: review of the Codex standalone release cleanup

Another session added `clean agents` Codex release cleanup (039b2b4, 038defe,
cfd066c) into the 0.9.7 section and published `v0.9.7-beta1` at cfd066c while
this review's fix was in flight. The user chose: review it, then promote.

Three fresh passes (Standards, Spec, Security) plus own reading. Fixed, each
test shown failing on a mutant:

- A release a process still executes was offered. After an upgrade, agents
  keep running the old release and spawn helpers from it by path; 11 processes
  ran from the current release on this Mac. One system-wide `lsof -d txt`
  (0.5 s, exit 0) under the installer lock now excludes it; failure refuses.
  Proven with a copy of the test binary run from a fixture release (macOS
  SIGKILLs a copied `/bin/sleep`), a CLI stub, and real vendor bytes in an
  isolated HOME (`zsh -c 'sleep 30; true'`: plain `sleep 30` is exec'd away).
- FIFO at a vendor file name hung scan (NONBLOCK); leading-zero versions
  accepted; lock identity rechecked after flock; rustix opens lacked CLOEXEC.
- Authority is now a `DeletionEntry` with a planted evidence case; two-tier
  docs amended; `sha2` recorded in SECURITY.md supply chain.

Premise checked in primary sources: installer (0a2eb46) uses `lockf 9` on
macOS, which man lockf(1) says is flock(2) with -k implied for an fd; it
prunes only `.staging.*`, never old releases.

Flake found and fixed in the fixture, not the product: a test's non-blocking
exclusive flock right after its scan hit WouldBlock ~1 in 8 while another test
spawned from the same binary. The fixture now retries within 5 s.
