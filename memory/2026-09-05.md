## 0.8.2: concurrent scanning, test slop, and an adversarial race test

Three things landed. The categories now scan concurrently, the test suite lost
its duplicated and vacuous parts, and the deletion sink finally has a test that
attacks it.

The concurrency is the interesting one because the risk is not speed, it is
truth. Nine categories on scoped threads, joined in registry order, means the
JSON document is byte-identical to the serial version — and that is provable
rather than asserted: over a 25-repository corpus the new parallel binary and
the released 0.8.1 serial binary produce the same SHA-256, and twelve
consecutive parallel runs produce that one digest. Exactly-once probing
survived too: still one `git log` per repository per scan, because each
repository's cell is an `Arc<OnceLock<..>>` cloned out from under the mutex, so
the lock is never held across the subprocess.

## What the reviews caught that the gates did not

Two independent review axes ran against the same diff. The standards axis found
that deleting `protects_home_and_user_secrets` had quietly removed the only
assertion that the home root itself is protected — the proptest only draws from
`PROTECTED_USER`, never the bare home, so one branch of `is_protected_abs` was
uncovered on a security boundary. The spec axis found that collapsing the
forged-authority tests into loops had dropped the pathless payload, so a forged
command finding carrying no path at all went untested in both Docker and
simulators. Neither is visible to a gate: the suite was green throughout.

Both fixes carry a positive control. Breaking the home-root branch on purpose
now fails the suite; accepting a pathless Docker finding on purpose now fails
the table.

## The test I got wrong three times

The adversarial race test asserted that no quarantine entry remains. That is
not an invariant. `restore_quarantined_target` deliberately declines to move
the entry back when the original name is occupied, and the racing mutator
occupies exactly that name — so the sink keeps both entries and reports that
nothing was deleted. Keeping the data is the safe outcome; overwriting it would
not be. I then over-corrected and asserted the leftover is a directory, which
fails when the swap lands such that the mutator's symlink is what got
quarantined.

The only invariant that holds under every interleaving is that no data is
destroyed. Forty consecutive full-suite runs pass on the third version. The
lesson is the ordinary one and I relearned it the ordinary way: an assertion
about a concurrent system is a hypothesis until the schedule that breaks it has
had its chance, and a test that passed twenty times on an idle machine is not
evidence about a loaded one.

## The ceiling we are choosing not to break

`dir_size` costs one `stat` per file. macOS `getattrlistbulk` would collapse
that to roughly one syscall per hundred entries, which is the single largest
remaining win. It has no safe wrapper in this dependency set and would need
`unsafe` FFI, and `unsafe_code = "forbid"` is load-bearing for a tool that
deletes files. That trade is now written into `SECURITY.md` so the next person
does not rediscover it and quietly reach for the faster answer.
