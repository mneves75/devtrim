# 2026-09-26

## 0.10.0: uv cache, purge, TUI selection

Started as a real `devtrim scan` on a Mac at 97% full (830 findings). Using it
found five defects, each fixed with a test that failed first:

- uv writes an empty `.git` into `sdists-v<N>` (uv 0.9.24
  `crates/uv-cache/src/lib.rs:439-449`), so the nested-repository refusal
  blocked the uv cache on every run. The sink tolerates exactly that shape under
  a valid `CACHEDIR.TAG`; every other shape still refuses, a FIFO included.
- Making uv removable exposed removal under a running uv. Apply now takes uv's
  own `<cache>/.lock` exclusively without waiting, as `uv cache clean` does.
- `trash-empty` stopped at the first refused item.
- Summaries called Trash moves "reclaimed": 25 GB "reclaimed" while `df` did
  not move.
- Git activity dates rendered in each entry's zone against a UTC cutoff, so the
  probe tests failed every evening in UTC-3.

Features follow a study of Mole V1.56.0 (`239c90d`, GPL-3.0), whose ergonomics
were reimplemented and whose matching was not ported:
- `purge`: node-modules and artifacts by project, largest first, applied
  through each category's owner;
- TUI selection that only narrows the approved plan;
- a scan summary that leads with categories.

Reviews:
- security review: no findings;
- Standards and Spec review: fixes landed in 55ac10f;
- mneves-verify: PASS from a different model (Fable);
- autoreview: Codex quota was out on both accounts, so the owner chose Fable as
  the engine; 05f7769..55ac10f came back scoped-clean.

Staging caught a defect the local suite could not. The downloaded
`v0.10.0-beta1` failed the PTY suite from its deep download directory. Each row
keeps only its path's end, so the detail pane is the one place a long path
appears whole, and it cut content silently: at 64×18 it had three rows.
- 093d67e fixed that: the pane grows, puts the selection state first and counts
  hidden lines.
- Review then found two holes in its word-breaking wrap. 036a760 fixed the
  first, per-code-point widths: a flag or a skin-tone emoji could split at the
  edge.
- The second was a space one column past the edge, hung where the renderer clips
  it, so `Application Support` read as one name. It was the third hole in that
  design (my own blank-row bug was the first), so acc53f9 removed the design
  rather than patching it: rows break only where the next grapheme would pass
  the edge.
- The release-gate review accepted acc53f9 with one residual: a space in a full
  row's last cell looks like padding. The next-patch fix is to break before such
  a space.
- The PTY harness now rebuilds the screen from the escape stream, because
  ratatui repaints only changed cells.
- A Fable verifier, working black-box from a PTY, passed every commit it was
  given: 093d67e, 036a760 and acc53f9, the last with 45/45 checks and controls.
- v0.10.0-beta2 and v0.10.0 are acc53f9.

Lesson: run the release's E2E against the downloaded artifact from where a
user puts it. A suite that was green from `target/debug` hid a path-length
defect that the first real directory exposed.
