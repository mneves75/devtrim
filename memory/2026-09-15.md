# 2026-09-15

## 0.9.4: whole-codebase review and security audit

The request was a full review of an already-released tree, so there was no diff
to review. Code-review tooling needs a fixed point; the whole-tree Codex review
got one from a scratch clone with a synthetic commit adding the reviewed paths
onto an empty root. Five independent passes ran: security (Rust boundaries),
security (supply chain), Standards, Spec, and a correctness hunt, plus web
research for dependency and toolchain currency.

Confirmed and fixed, each with a test that failed first:

- Preview executed repository-configured programs through `git log`.
- TUI type-ahead approved an undisplayed permanent plan.
- `trash-empty --apply` skipped the shared gate; its size basis differed from
  the plan's.
- Quarantine restore could overwrite a recreated name (now `RENAME_EXCL`).
- Clap parse errors passed bidi controls from argv.
- `lsof` escapes defeated build liveness; ambiguous `^X` now refuses.
- Xcode.app builds were invisible to DerivedData liveness.
- `status` broke under `pt_BR` (decimal commas) and raised the health score.
- `analyze` entered foreign devices on Enter; lower bounds exited 0.
- Release handoff bound by name only; policy accepted forbidden grants.

Rejected with reasons: optimize accepting several named `--task` flags (each
is named, which is the consent the rule asks for); installers using change time
(unsettable in fixtures and moved by any metadata change — documented instead);
Docker VM finding preserved alongside a daemon error (the trait returns findings
or an error; docs corrected to match the recorded trade).

Dependencies: `trash` 5.2.8, `toml` 1.1.5 (1.1.6 held by the new seven-day
cooldown), `clap_mangen` 0.3.3 with a byte-identical man page. Rust 1.98.1 is
still current and a fresh RustSec database reports nothing.

Not done: allocated-block size reporting and recording Trash destinations in
the journal were the research pass's top suggestions; both are features, not
defects, and are left for their own release.

## 0.9.5: findings from a real low-disk cleanup

A manual cleanup of this Mac (1.7 GB free) was compared with a read-only
`devtrim scan --json`. Web research covered Xcode DeviceSupport regeneration
(`xcodebuild -prepareDeviceSupport`, Xcode 16.3 notes), `simctl` runtime and
device commands, Playwright's browser GC (`registry/index.ts`), OrbStack and
Docker Desktop space return, and moby/BuildKit build-cache accounting.

Fixed, each with a test that failed first: Xcode offered non-directory and
symlink children; the build-cache estimate used RECLAIMABLE under `prune -a`;
VM-image notes promised compaction timing; the DeviceSupport note overclaimed
regeneration. Added a report-only working-simulator disclosure from
`dataPathSize`, parsed apart from the device authority.

Reviews: Standards, Spec and Security sub-agents, then Codex autoreview. They
found an ACTIVE column parsed on ignored rows, disclosure fields sharing the
authority struct, a silent omission, and missing context and positive
controls; all fixed. Self-found before review: the disclosure made simulator
apply refuse and walk the whole tree.

## 0.9.6: lsof liveness race

Symptom from a real apply, reproduced (probe 2/5, released preview 2/10).
Verified macOS semantics before designing: live+dead PID prints the live one
and exits 1; a dead or unreadable PID alone prints nothing and exits 1; `pgrep`
excludes its ancestors unless `-a`. Fix: per-process parse, recheck unreported
PIDs, one lookup for successors, `-a` in both probes, two new planted cases.
