# 2026-09-28

## 0.10.4: two windows, Codex worktrees, orphaned worktrees

The owner answered the three open 0.10.3 decisions with "do it" and asked why the window was
10 days, and whether it could be shorter. Measured read-only with a throwaway HOME and
`--root ~/dev`: 10 or 7 days offered 1.2 GB, 3 days 4.5 GB, and 1 day 36.3 GB across 32
projects.

Answering exposed a design flaw. `active_days` also gated `agents` history and `installers`,
which nothing regenerates, so lowering the window for build output would have offered
irreplaceable history sooner. Found by the Spec review after `active_days = 3` had been
written to the owner's config; nothing had been deleted. Fix: `retain_days` for those two.
Unset, it is max(active_days, 30) (`safety::activity_windows`). Planted cases
`agents/retention-window` and `installers/retention-window`.

Worktrees, from primary sources:
- Codex creates them in `$CODEX_HOME/worktrees` (openai/codex#10599), so `.codex/worktrees`
  was added.
- Claude Code creates them inside the repository, `<repo>/.claude/worktrees/` (CLI and desktop
  docs). Mole's `~/.claude/worktrees` appears only in a hook example, so it was not added.
- `~/.codex*/worktrees` is absent on this Mac.
- A linked worktree whose repository is gone made every Git query fail and emptied the whole
  category. `project::orphaned_worktree` now skips it and names it.

The skip notes name `active_days in ~/.config/devtrim.toml` (`safety::CONFIG_DISPLAY_PATH`).

Reviews:
- Standards/Spec. Spec found the `active_days` conflation and the orphan failure mode.
- Security review: no findings. It flagged a non-UTF-8 `.git` file failing the category, which is
  fixed by parsing bytes.
- autoreview (Codex, P2): the parser split at the first newline and trimmed spaces, unlike Git,
  so a live worktree whose gitdir holds a newline or a trailing space would read as orphaned. It
  now matches git v2.51.0 `read_gitfile_gently`.

Owner Mac, all with explicit approval (AskUserQuestion):
- purge at a 1-day window: 272 items, 33.8 GB to Trash;
- then `active_days = 3`;
- six idle simulators deleted after rechecking that each was Shutdown and its `lastUsedAt`
  unchanged: four generic ones plus "MinutaDraft Store 13" and
  "CaptureVault-PhotoRecovery-Test";
- `trash-empty --confirm=33 --yolo`: 273 items, the extra one being the Trash's own `.DS_Store`.

Free space went from 33 to 65 GiB. `simctl` JSON has no usable last-boot field;
`device.plist` `lastUsedAt` is the signal.

Lesson: one setting that decides two different things will be tuned for one of them. Split it
before someone lowers it.
