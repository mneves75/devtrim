# 2026-09-27

## 0.10.3: where purge looks, and why it said nothing

Started as a real `devtrim purge --apply`. It trashed 43 items, all under `~/dev`, 40 of
them one-byte fixtures devtrim's own tests had left under `target/` when they failed. The
owner asked why it did not look at the whole disk, or at least the whole account.

The answer was that nobody had configured roots, so it looked only in `~/dev`, and nothing
in the output said so. Fixes, each with a test that failed first:
- Default roots are the conventional project folders that exist
  (`safety::DEFAULT_PROJECT_ROOTS`). This is Mole V1.56.0's
  `MOLE_PURGE_DEFAULT_SEARCH_PATHS` plus `Developer`, without `Library/CloudStorage` or the
  agent worktree containers. The whole home is ruled out: TCC prompts for
  Desktop/Documents/Downloads, iCloud's dataless files, and no Git owner outside project
  folders. A default folder is skipped with a warning when it is unreadable, broken, or
  links to the home folder or above it (autoreview P2: `~/www -> ~` would have made the whole
  home a default root). One linked into another default is scanned once.
- Every human preview that walks roots, TUI included, says `info scan roots: ...`, naming
  their origin (`RootsOrigin`). JSON is unchanged.
- A `node_modules` with build output strictly between its owning repository and itself
  (Next.js `.next/standalone/node_modules`) is never offered, and apply refuses it. The walk
  prunes build output below the root. This removed the double count in `purge` and hides
  repositories left inside a Cargo `target`.
- The first bound was "any ancestor", which broke every fixture under `devtrim/target`: the
  checkout's own `target` is build output. It is now bounded by the owning repository. The
  walk's pruning scopes the search the way roots do, and apply does not recheck either.
- `ops::TestFixture` removes a fixture while a failing test unwinds. The 674 older leftovers
  remain under `target/`; deleting them is the owner's call.
- The skip notes name the activity window and the busy repositories. On the owner's Mac, 89
  items were skipped because a build process was running.
- `CACHEDIR.TAG` is read in one open with no-follow and non-blocking, like uv's tag, instead
  of an lstat followed by an open.

Reviews:
- Standards/Spec (code-review skill): the TUI lacked the roots note, and an unreadable
  default failed every command. Both fixed, with a CLI test added.
- Security review: no exploitable findings. It raised hardening on the CACHEDIR.TAG read,
  which is now applied.
- autoreview (Codex, P2): one finding, the home-link default. Fixed with planted case
  `roots/default-home-link`.
- mneves-verify with Fable 5.1: PASS on all 8 criteria. Its fixture-count check was void
  because its glob matched nothing; the builder's count stayed 674 before and after. Its
  apply run left four tiny fixture folders in the real `~/.Trash`, because the Trash API
  uses the per-user Trash, not `$HOME`.

Gates on the final tree:
- focused and offline, which includes 58 planted cases and MSRV 1.88;
- 5 × 60 s of fuzzing;
- `cargo audit`;
- TruffleHog on the changed files. The 6 unverified candidates are in the git-ignored
  `.scratch/`.
- video install, audit, lint, format and build.

Lesson: a scan whose scope is invisible is its own defect. An empty or small result reads
as a clean machine unless the preview names where it looked.

Open owner decision: add `~/.codex/worktrees` and `~/.claude/worktrees` (Mole includes
them). The default taken is no: they are absent here, and they hold agent session state.
